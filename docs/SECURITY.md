# Безопасность

## Что реализовано
- Пароли хранятся только как BCrypt-хэш (cost 12); пароль нигде не логируется и не возвращается в ответах.
- Аутентификация по JWT (HS256), срок жизни настраивается; ключ ≥ 32 символов проверяется при старте.
- Роли: `ADMIN` (удаление, создание сотрудников), `LIBRARIAN` (остальные операции). Все эндпоинты, кроме `/api/auth/login`, требуют токен.
- Открытой саморегистрации нет: учётные записи создаёт только администратор.
- Сообщение о неверном логине/пароле одинаково, проверка пароля выполняется и для несуществующего пользователя.
- SQL-инъекции исключены: только параметризованные запросы JPA/JPQL.
- Входные данные валидируются (Bean Validation), поле сортировки проверяется.
- Ошибки не раскрывают stack trace, имена таблиц и ограничений БД.
- Схема БД создаётся Flyway, `ddl-auto=validate`; CHECK-ограничения защищают целостность (остатки экземпляров ≥ 0).
- Конкурентная выдача защищена блокировкой строки (`SELECT ... FOR UPDATE`).
- Заголовки: `X-Frame-Options: DENY`, `Content-Security-Policy`, `X-Content-Type-Options`.
- В docker-compose БД доступна только на `127.0.0.1`.

## Секреты и GitHub
- Пароли БД, `JWT_SECRET`, данные администратора — только в переменных окружения / файле `.env` (в `.gitignore`).
- В репозитории только `.env.example` с плейсхолдерами.
- В коллекции Postman переменные `adminUser`/`adminPassword`/`token` пустые.

## Известные ограничения (честно)
1. Для Spring Boot выбрана поддерживаемая стабильная ветка 4.1.1; перед эксплуатацией обновляйте зависимости по результатам Dependabot и CI.
2. Нет ограничения числа попыток входа (brute-force). Для эксплуатации добавить rate limiting (например, Bucket4j) и блокировку.
3. Токен нельзя отозвать до истечения срока (нет refresh/blacklist), но удалённый пользователь теряет доступ сразу (проверка по БД).
4. Нет HTTPS на уровне приложения — в эксплуатации ставить за reverse proxy с TLS.
5. GitHub Actions собирает проект, запускает тесты и Dependency-Check; Dependabot проверяет Maven-зависимости и GitHub Actions. Dependency-Check завершает сборку ошибкой при найденных уязвимостях с CVSS 7.0 и выше. Для снижения ограничений NVD рекомендуется добавить `NVD_API_KEY` в Actions secrets.
6. Локальную сборку в среде разработки выполнить не удалось: Java, Maven и Docker не установлены. CI выполняет проверку на Java 21; первый успешный запуск workflow подтвердит совместимость обновления.
